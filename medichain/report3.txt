SECTION 5 — BUGS AND CHALLENGES

Major bugs / integration issues faced and resolution (3–5 specific items):
1. Hash mismatch on transfer — fixed by canonicalising record payload serialization and computing bundle hash using hospital write-time canonicaliser (`_payload_hash`) so sender and receiver agree on canonical JSON.
2. Incorrect record visibility for patients — resolved by tightening ownership checks in `service_get_finalized_medical_record_detail` and returning only scoped records via `MedicalRecordMeta` lookups.
3. Dashboard counts inaccurate — fixed in `service_get_dashboard_data` logic and API view to use distinct record_id aggregation on `MedicalRecordMeta`.
4. Lab name field mismatch (lab_name vs name) — fixed to use `Lab.name` across patient-facing APIs.
5. Audit log scoping — initially logs were not filterable by hospital scope; added `scope_hospitals` JSON field and updated `log_action` usage and `view_logs` filters.

Biggest technical challenges this phase:
- Designing a deterministic canonicalisation for payload hashing that remains stable across DB reads and JSON serialization differences.
- Bridging default-shared models and hospital-local tables safely (thread-local DB routing) without leaking context across requests.
- Keeping consent state machine correct across three actors (requesting hospital, patient, owning hospital) while preserving auditability.
